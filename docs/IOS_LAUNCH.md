# iOS Launch Guide — StreakFlow

How to take StreakFlow (Flutter, bundle ID `com.codesapience.streakflow`) to
the Apple App Store **without a Mac**, using GitLab as the source of truth.

Status as of 2026-10-05: the iOS project exists and compiles unsigned (GitHub
Actions `build-ios` job), but it is **not store-ready** — see
[Section 3](#3-code-changes-required-before-the-first-ios-build).

---

## 1. Choosing the build environment

iOS apps can only be compiled and signed on macOS. This GitLab project's plan
has **no hosted macOS runners** — jobs tagged `saas-macos-medium-m1` fail with
`no_matching_runner` (see the header of `.gitlab-ci.yml`).

| Option | Cost | Pros | Cons |
|---|---|---|---|
| **A. Codemagic connected to GitLab** *(recommended)* | Free tier: 500 macOS build min/month | Repo stays on GitLab; automatic code signing via App Store Connect API key (no Mac/Keychain needed); built-in TestFlight upload | One more service to manage |
| B. GitLab Premium + hosted macOS runners | ~US$29/user/month | Everything in one place (`.gitlab-ci.yml`) | Paid; macOS runners are still beta; you handle signing yourself |
| C. GitHub mirror (`.github/workflows/ci.yml`) | Free (public repo) | `build-ios` job already exists | Two CI systems; signing secrets on a public repo's Actions (secrets stay hidden, but take care with workflows triggered by forks) |

**Recommendation:** keep GitLab CI for analyze/test/Android, and use
**Codemagic** for iOS builds and TestFlight uploads.

## 2. Prerequisites (accounts & paperwork)

### 2.1 Apple Developer Program — US$99/year

- Enroll at <https://developer.apple.com/programs/enroll/>.
- **Organization** enrollment (seller shown as "Code Sapience") needs a
  **D-U-N-S number** for the business — free, but can take **1–3 weeks**.
  Look it up / request it via Apple's D-U-N-S lookup tool.
- **Individual** enrollment is faster (1–2 days) but the seller name is your
  personal legal name. Changing from individual to organization later is
  possible but slow.
- Enable two-factor authentication on the Apple ID first.
- **Start this now** — it is the longest lead-time item.

### 2.2 App Store Connect setup (<https://appstoreconnect.apple.com>)

1. **Agreements, Tax, and Banking** → accept the **Paid Apps** agreement and
   fill in bank + tax forms. *In-app purchases do not work until this is
   "Active".*
2. **Certificates, Identifiers & Profiles** (developer.apple.com) →
   Identifiers → register App ID `com.codesapience.streakflow`.
   - Capabilities: **In-App Purchase** (on by default). Push Notifications is
     *not* needed — reminders are local notifications.
3. **Users and Access → Integrations → App Store Connect API** → generate a
   **Team key** with **App Manager** role. Save:
   - the `.p8` file (downloadable **once only**)
   - Key ID
   - Issuer ID
4. **My Apps → +** → New App:
   - Platform: iOS
   - Name: StreakFlow (must be unique on the store)
   - Primary language, bundle ID `com.codesapience.streakflow`
   - SKU: e.g. `streakflow-ios`
5. **Monetization → Subscriptions** → create a subscription group (e.g.
   "StreakFlow Premium") and a product with ID **`streakflow_premium`**
   (matches `PremiumConfig.subscriptionProductId`). Add price, duration,
   localized display name/description, and a review screenshot of the paywall.
6. **Users and Access → Sandbox → Test Accounts** → create a sandbox tester
   (use a fresh email, not your real Apple ID) for testing purchases.

### 2.3 AdMob

- In the AdMob console add a **new iOS app** (it can be linked to the App
  Store listing after release).
- Create iOS ad units: **banner, interstitial, rewarded**.
- Note the iOS **App ID** (`ca-app-pub-…~…`) and the three unit IDs
  (`ca-app-pub-…/…`).
- In AdMob **Privacy & messaging**, create an **IDFA explainer message**
  (shown before Apple's tracking prompt) alongside the existing GDPR message.

### 2.4 Hardware

- A **physical iPhone** for TestFlight testing. With no Mac there is no
  simulator — use your own device or a friend's/tester's.

### 2.5 Store listing assets

| Asset | Requirement |
|---|---|
| Screenshots | 6.9" iPhone: 1320×2868 portrait (3–10 images). iPad 13" only if the app supports iPad (see 3.6). |
| App icon | 1024×1024 PNG, no alpha (generated by `flutter_launcher_icons`, `remove_alpha_ios: true`) |
| Privacy policy URL | streakflow-site `privacy-policy.html` (update it to mention iOS / Apple) |
| Support URL | e.g. streakflow-site home page or a contact page |
| Terms of Use (EULA) | Required for auto-renewing subscriptions — link Apple's standard EULA or `terms.html` in the app description |
| Description, keywords (100 chars), promotional text, subtitle | Write in App Store Connect |
| Age rating | Questionnaire in App Store Connect |
| App Privacy ("nutrition labels") | Declare AdMob data: identifiers (device ID), usage data, diagnostics; "Used to track you" if personalized ads are served |

Screenshots without a Mac: take them on the TestFlight build on a real iPhone,
or capture them from Codemagic's simulator (integration test + `xcrun simctl
io booted screenshot`).

## 3. Code changes required before the first iOS build

### 3.1 In-app purchases — StoreKit gateway (**blocker**)

- `lib/core/billing/premium_store.dart:81` always returns
  `PlayBillingGateway()`.
- `play_billing_gateway.dart` filters products with
  `whereType<GooglePlayProductDetails>()`, so on iOS **no products are found
  and Premium cannot be bought**.
- To do:
  - Add `in_app_purchase_storekit` and an `AppStoreBillingGateway`
    implementing the existing `BillingGateway` interface.
  - Select the gateway by platform (`Platform.isIOS`).
  - Add a visible **Restore Purchases** button on the paywall (App Review
    guideline 3.1.1).
  - Paywall must show (guideline 3.1.2): subscription title, length, price
    per period, auto-renew wording, and links to **Privacy Policy** and
    **Terms of Use**.
  - Don't mention Google Play / Android anywhere visible on iOS.

### 3.2 AdMob iOS IDs (**blocker** for ads revenue)

- `ios/Flutter/AdMob.xcconfig` → replace Google's sample
  `ADMOB_IOS_APP_ID = ca-app-pub-3940256099942544~1458002511` with the real
  iOS App ID.
- `config/ads/admob.production.json` → fill `ADMOB_IOS_BANNER_ID`,
  `ADMOB_IOS_INTERSTITIAL_ID`, `ADMOB_IOS_REWARDED_ID`.
- If iOS IDs are missing, `AdConfig` falls back to "ads disabled" (safe, but
  no revenue).

### 3.3 `ios/Runner/Info.plist`

- **`NSUserTrackingUsageDescription`** — required for the App Tracking
  Transparency prompt that AdMob/UMP shows. Example: *"This identifier will be
  used to deliver more relevant ads to you."*
- **`SKAdNetworkItems`** — currently only `cstr6suwn9`. Replace with Google's
  full recommended list (<https://developers.google.com/admob/ios/3p-skadnetworks>).
- **`NSPhotoLibraryUsageDescription`** — add because `file_picker` links
  photo-library APIs; App Store upload warns/rejects without it.
- Already present and correct: `ITSAppUsesNonExemptEncryption = false`,
  `GADApplicationIdentifier`, `CFBundleDisplayName = StreakFlow`.

### 3.4 Notifications — `ios/Runner/AppDelegate.swift`

`flutter_local_notifications` needs the notification-center delegate set, or
reminders won't show while the app is in the foreground:

```swift
if #available(iOS 10.0, *) {
  UNUserNotificationCenter.current().delegate = self as UNUserNotificationCenterDelegate
}
```

(inside `didFinishLaunchingWithOptions`, before `super.application(...)`).
Also confirm the app requests notification permission on iOS at the right
moment (not on first launch without context).

### 3.5 Privacy manifest — `ios/Runner/PrivacyInfo.xcprivacy`

Apple requires an app-level privacy manifest. Declare:

- `NSPrivacyTracking`: `true` if personalized ads are used, with AdMob
  tracking domains.
- `NSPrivacyAccessedAPITypes`: `UserDefaults` (reason `CA92.1`),
  file timestamp (`C617.1`) as used by `shared_preferences` / Isar /
  `path_provider`.
- `NSPrivacyCollectedDataTypes`: matching the App Privacy labels.

Add the file to the Runner target in `project.pbxproj`.

### 3.6 iPhone-only (recommended)

Set `TARGETED_DEVICE_FAMILY = 1` in `ios/Runner.xcodeproj/project.pbxproj`
(Runner target, all configs). This removes the iPad screenshot requirement and
iPad layout review. The app still runs on iPads in compatibility mode. Also
consider removing landscape from `UISupportedInterfaceOrientations` if the UI
isn't designed for it.

### 3.7 Other checks

- Deployment target `IPHONEOS_DEPLOYMENT_TARGET = 14.0` — fine for all
  current plugins.
- Version: `pubspec.yaml` `version: 1.0.0+N`. iOS build numbers are
  independent of Android but must increase for every upload; simplest is to
  keep them in step (next ≥ 13).
- `in_app_review` — works on iOS (StoreKit review prompt); App Store ID
  needed only for `openStoreListing`.
- Backup export/import (`file_picker`, `share_plus`) — test on device; iOS
  share sheet needs `sharePositionOrigin` on iPad.
- `audioplayers` — confirm sounds respect the silent switch.

## 4. Build pipeline — Codemagic + GitLab (step by step)

### 4.1 One-time setup

1. Sign up at <https://codemagic.io> with your GitLab account.
2. **Add application** → GitLab → `codesapience/streak_calculator`.
   - Project path: the Flutter app lives at the repo root
     (`streak_calculator_flutter` is the repo).
3. **Teams → Integrations → Developer Portal** → add the App Store Connect
   API key (name it e.g. `streakflow_asc`): Issuer ID, Key ID, `.p8` file.
4. **Environment variables** (Application → Environment variables), group
   `ios_secrets`, marked **Secure**:
   - `ADMOB_PRODUCTION_JSON_BASE64` — base64 of
     `config/ads/admob.production.json` (if that file is not committed).
5. Codemagic reads `codemagic.yaml` from the repo root.

### 4.2 `codemagic.yaml` (template)

```yaml
workflows:
  ios-release:
    name: iOS release → TestFlight
    max_build_duration: 60
    instance_type: mac_mini_m2
    integrations:
      app_store_connect: streakflow_asc
    environment:
      flutter: 3.44.4
      xcode: latest
      groups:
        - ios_secrets
      ios_signing:
        distribution_type: app_store
        bundle_identifier: com.codesapience.streakflow
    triggering:
      events:
        - tag
      tag_patterns:
        - pattern: 'ios-v*'
    scripts:
      - name: Restore ad config
        script: |
          if [ -n "$ADMOB_PRODUCTION_JSON_BASE64" ]; then
            echo "$ADMOB_PRODUCTION_JSON_BASE64" | base64 --decode > config/ads/admob.production.json
          fi
      - name: Prepare SwiftPM plugin folder
        script: mkdir -p build/ios/SourcePackages
      - name: Get packages
        script: flutter pub get
      - name: Analyze & test
        script: |
          flutter analyze
          flutter test
      - name: Set up code signing
        script: xcode-project use-profiles
      - name: Build IPA
        script: |
          flutter build ipa --release \
            --dart-define-from-file=config/ads/admob.production.json \
            --export-options-plist=/Users/builder/export_options.plist
    artifacts:
      - build/ios/ipa/*.ipa
      - /tmp/xcodebuild_logs/*.log
    publishing:
      app_store_connect:
        auth: integration
        submit_to_testflight: true
```

With `ios_signing` + the API-key integration, Codemagic creates/fetches the
**Apple Distribution certificate** and **App Store provisioning profile**
automatically — no Mac or Keychain required.

### 4.3 Each release

1. Bump `version:` in `pubspec.yaml` (e.g. `1.0.0+13`), merge to GitLab.
2. Tag and push: `git tag ios-v1.0.0+13 && git push origin ios-v1.0.0+13`
   (or start the workflow manually in the Codemagic UI).
3. Codemagic builds, signs, and uploads to App Store Connect.
4. Apple processes the build (~10–30 min); it appears under **TestFlight**.
5. Answer the export-compliance question if asked (already pre-answered by
   `ITSAppUsesNonExemptEncryption = false`).

## 5. Alternative: pure GitLab (Premium plan)

If the project moves to GitLab Premium/Ultimate:

1. Enable hosted macOS runners for the project.
2. Signing without a Mac — create the certificate with OpenSSL on Windows:

   ```bash
   openssl genrsa -out ios_dist.key 2048
   openssl req -new -key ios_dist.key -out ios_dist.csr \
     -subj "/emailAddress=you@example.com/CN=Code Sapience/C=IN"
   # Upload ios_dist.csr at developer.apple.com → Certificates → Apple Distribution
   # Download distribution.cer, then:
   openssl x509 -inform DER -in distribution.cer -out ios_dist.pem
   openssl pkcs12 -export -legacy -inkey ios_dist.key -in ios_dist.pem \
     -out ios_dist.p12 -passout pass:YOUR_PASSWORD
   ```

   Then create an **App Store provisioning profile** for
   `com.codesapience.streakflow` using that certificate and download it.
   (Alternatively use `fastlane match` with the API key.)
3. Add masked/protected CI/CD variables:
   `IOS_DIST_P12_BASE64`, `IOS_DIST_P12_PASSWORD`,
   `IOS_PROFILE_BASE64`, `APPLE_TEAM_ID`,
   `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8_BASE64`.
4. Add a job:

   ```yaml
   build_ios:
     stage: build
     tags: [saas-macos-medium-m1]
     image: macos-15-xcode-16
     needs: [analyze, test]
     rules:
       - if: '$CI_COMMIT_TAG =~ /^ios-v/'
     script:
       - security create-keychain -p ci build.keychain
       - security default-keychain -s build.keychain
       - security unlock-keychain -p ci build.keychain
       - echo "$IOS_DIST_P12_BASE64" | base64 -d > dist.p12
       - security import dist.p12 -k build.keychain -P "$IOS_DIST_P12_PASSWORD" -T /usr/bin/codesign
       - security set-key-partition-list -S apple-tool:,apple: -s -k ci build.keychain
       - mkdir -p ~/Library/MobileDevice/Provisioning\ Profiles
       - echo "$IOS_PROFILE_BASE64" | base64 -d > ~/Library/MobileDevice/Provisioning\ Profiles/streakflow.mobileprovision
       - mkdir -p build/ios/SourcePackages
       - flutter pub get
       - flutter build ipa --release --export-options-plist=ios/ExportOptions.plist
       - echo "$ASC_KEY_P8_BASE64" | base64 -d > AuthKey.p8
       - xcrun altool --upload-app -f build/ios/ipa/*.ipa -t ios
           --apiKey "$ASC_KEY_ID" --apiIssuer "$ASC_ISSUER_ID"
     artifacts:
       paths: [build/ios/ipa/*.ipa]
   ```

   `ios/ExportOptions.plist` needs `method = app-store-connect`, `teamID`,
   and `provisioningProfiles` mapping the bundle ID to the profile name.

Certificates expire after 1 year; profiles must be regenerated with them.

## 6. Testing (TestFlight)

1. App Store Connect → TestFlight → **Internal Testing** → add yourself
   (up to 100 internal testers, no review needed).
2. Install the **TestFlight** app on the iPhone, accept the invite, install.
3. Test checklist:
   - [ ] First launch, onboarding, splash screen and icon
   - [ ] Create/edit/delete habits, streak calculations, charts
   - [ ] Local notification reminders (app closed **and** open), permission prompt
   - [ ] Ads: UMP consent → ATT prompt → banner/interstitial/rewarded load
   - [ ] Premium purchase with **sandbox** account, ads removed after purchase
   - [ ] **Restore Purchases** on a reinstall
   - [ ] Backup export (share sheet) and import (file picker)
   - [ ] In-app review prompt, external links (privacy, terms)
   - [ ] Dark mode, Dynamic Type / large text, small screen (iPhone SE)
4. **External Testing** (up to 10,000 testers) needs a short Beta App Review
   — optional before submitting.

## 7. Submission

1. App Store Connect → the app → **iOS App 1.0** → select the TestFlight build.
2. Fill in: screenshots, description, keywords, support URL, marketing URL,
   copyright, age rating, App Privacy, pricing (Free) and availability.
3. Attach the **`streakflow_premium` subscription** to this version
   ("In-App Purchases and Subscriptions" section) — first subscriptions must
   be submitted together with an app version.
4. **App Review Information**: contact details and notes, e.g. how to reach
   the paywall; no login is needed.
5. Release option: manual release recommended for the first version.
6. **Submit for Review** — typically 24–72 hours.

### Common rejection reasons to pre-empt

- Missing Restore Purchases button or incomplete subscription disclosure (3.1.2)
- ATT prompt missing while ads track users (5.1.2)
- Mentions of Android / Google Play in the UI or screenshots (2.3.10)
- Broken privacy-policy link or policy that doesn't cover the app (5.1.1)
- Crashes on launch in the release build — always smoke-test the TestFlight
  build on a real device first
